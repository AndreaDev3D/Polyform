# v0.4 Porting Plan — Rust/WASM Core & WebGPU Renderer

> Preparation document for the v0.4 "Performance Core" phase ([Roadmap](Roadmap.md)).
> It inventories exactly what exists after v0.3.0, defines the API contracts a
> Rust module must satisfy to replace its TypeScript twin, and fixes the port
> order and verification strategy — so v0.4 is execution, not archaeology.

## Ground rules (from ADR-002)

1. **Module-by-module, never big-bang.** Each engine module is replaced behind
   its existing TypeScript function signatures; a thin `engine/backend.ts`
   switch decides TS vs WASM per module (feature flag in dev, defaults flipped
   as parity is proven).
2. **The file format does not change.** `scene.bin` (PFRM/MessagePack, schema
   v3) and `history.sqlite` are the contract; [schema.fbs](schema.fbs) is the
   reference object model for Rust struct definitions (serde now, FlatBuffers
   when flatc lands per ADR-004).
3. **Differential testing is the gate.** The existing vitest suites (49 tests)
   run against BOTH implementations; a fuzz harness feeds random documents to
   TS and WASM and diffs outputs. A module ships only at 100% parity or with
   documented, intentional improvements (e.g., exact CSG beating flattened
   booleans).

## The three API contracts

The renderer/UI call exactly three engine surfaces; Rust must reproduce them
bit-for-bit before internals are free to change:

1. **SceneGraph** — `addNode / removeNode / moveNode / updateNode / childListOf / parentOf / worldMatrix / worldAABB / renderOrder / zRank / rootIds / pages`. Ids remain strings; matrices remain `{a,b,c,d,e,f}`.
2. **PatchOp** — the JSON op grammar (`add/remove/update/move/page-*/styles-set`) with apply+invert symmetry. Existing journals MUST replay identically (fixture test: a recorded v0.1–v0.3 journal replayed on both engines ends in identical documents).
3. **Derived passes** — `runDerivedPasses(scene)` semantics: instance sync → text autoresize → auto-layout → container normalize → GC, iterated to fixpoint (bounded). Same fixpoints, same iteration bounds.

## WASM embedding plan

- `crates/polyform-core` (cdylib) built with wasm-pack; loaded in the renderer
  (main thread first; Dedicated Worker + SharedArrayBuffer once the renderer
  reads vertex buffers directly, per Technical-Specification §1.1).
- Boundary encoding: msgpack bytes for bulk (documents, subtrees), plain JSON
  for ops (journal parity). No per-node getter chatter across the boundary —
  batch APIs only.
- Determinism: TS numbers are f64 — Rust uses f64 throughout (NOT f32, despite
  the original spec sketch) so differential tests can demand exact equality.
- `newId()` stays host-side (injected), keeping WASM pure and replay-friendly.

## WebGPU renderer (parallel track)

- New `render/webgpu/` backend implementing the same draw-the-scene entry
  points as `canvas2d.ts` (ADR-003); runtime fallback to Canvas2D stays.
- Pipeline: tessellation in Rust (lyon) → vertex/index buffers → instanced
  draws; glyph atlas fed by the P4 text stack; backdrop blur as a scoped
  texture sample (closes F-16); dashed/aligned strokes done properly (F-04).
- Exit test: 100k-shape document pans at 60fps on integrated graphics
  (Product-Overview's headline claim, currently untested at that scale — the
  fuzz harness gains a document generator for this).

## Verification checklist (each module, before flag-flip)

- [ ] vitest suite green against WASM via the backend switch
- [ ] fuzz diff (1k random documents/ops) TS↔WASM: zero divergence
- [ ] recorded-journal replay fixture: identical final scene bytes
- [ ] perf: ≥2x TS on the module's micro-bench, or a written justification
- [ ] bundle size delta noted (wasm binary is asar-unpacked like sql.js, F-06)

## Suggested sequencing

```
Sprint A: crate scaffold + backend switch + geometry/shapes/spatial (P1)
Sprint B: booleans exact CSG (P1) + scene/commands (P2) + journal replay fixture
Sprint C: layout/constraints/components (P2-P3) + serialization + hit-test
Sprint D: WebGPU pipeline to parity on fills/strokes/effects
Sprint E: text stack (HarfBuzz) + glyph atlas + 100k-shape exit test
```

Rust 1.97 is already on the dev machine; `wasm32-unknown-unknown` target and
`wasm-pack` are the only toolchain additions (CI: `dtolnay/rust-toolchain` +
cache, added to build.yml in Sprint A).
