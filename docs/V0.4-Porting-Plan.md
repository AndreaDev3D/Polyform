# v0.4 Porting Plan — Rust/WASM Core & WebGPU Renderer

> Preparation document for the v0.4 "Performance Core" phase ([Roadmap](Roadmap.md)).
> It inventories exactly what exists after v0.3.0, defines the API contracts a
> Rust module must satisfy to replace its TypeScript twin, and fixes the port
> order and verification strategy — so v0.4 is execution, not archaeology.

## Status

**Sprint A shipped (2026-08-01).** `crates/polyform-core` exists (wasm-bindgen,
rstar; 13 host-side cargo tests), with `geometry.rs`, `shapes.rs`, and
`spatial.rs` ported line-for-line from their TS twins and a batch-only
Float64Array boundary (`wasm.rs` ↔ `engine/wasm/codec.ts`). The
`engine/backend.ts` switch routes `shapes` and `spatial` per flag; geometry
deliberately has no runtime flag yet (see gate results). Loading, artifact,
and CSP decisions are recorded in ADR-015.

Sprint A gate results (`npm run bench`, 10k-entry workloads, Windows/x64):

| Micro-bench | TS | WASM | Verdict |
| :-- | --: | --: | :-- |
| Spatial bulk-load 10k boxes | 5.39 ms | 2.42 ms | **WASM 2.23x — flag default `wasm`** (rebuild runs on every edit) |
| Spatial 200 box queries | 0.26 ms | 0.40 ms | rbush 1.5x — µs-scale either way; load dominates |
| Flatten one subpath | 1.3 µs | 4.1 µs | **TS wins per-call** — boundary encode/decode dominates |
| Outline one rounded rect | 0.27 µs | 1.4 µs | TS wins per-call |
| SVG path data, 50 subpaths | 0.31 ms | 0.65 ms | TS wins (string crossing) |
| 1000 matrix multiplies | 25 µs | 241 µs | TS 9.5x — why geometry has no per-call flag |

The written justification the checklist demands: fine-grained math will never
win across a per-call WASM boundary. The Rust ports of geometry/shapes earn
their keep as the substrate for Sprint B+ — booleans, hit-test, and scene
consume outlines **inside** Rust with zero crossings — and the parity suite
(13 tests, 1,000 seeded fuzz cases per function, exact IEEE equality on pure
arithmetic, 1e-12 on libm transcendentals) already proves them equivalent.
`shapes` flips its default when its consumers move.

**Sprint B, part 1 shipped (2026-08-01).** Exact bezier CSG (`booleans.rs`,
flo_curves) is the default boolean evaluator — 2.02x faster than
polygon-clipping AND correct on curves (closes F-03). Gates that shipped it:
Rust unit tests incl. an analytic circle-lens area check, a ground-truth fuzz
gate (sampled membership vs op semantics — deliberately NOT a TS diff, since
polygon-clipping's throw-fallback makes the TS result wrong on degenerate
input), and trap-containment (`poisonWasmEngine`: any WASM runtime failure
drops the whole engine back to TS for the session). Two flo_curves findings
worth keeping: control points ON segment endpoints (zero end-tangents) break
its intersection math — straight segments must use the 1/3–2/3
parameterization — and its path ops do not follow empty-set algebra
(`path_intersect(∅, b)` leaks `b`), so the op fold guards empties explicitly.
The journal replay contract fixture (contract #2's acceptance test) is also
in: `journal-replay.test.ts` + frozen snapshot.

**Sprint B complete (2026-08-01).** `scene.rs` ports the SceneGraph AND the
PatchOp engine (scene.ts + commands.ts). Representation decision: nodes/pages
live as schema-agnostic JSON trees (serde_json, `preserve_order` +
`float_roundtrip`) behind typed accessors — byte-exact document round-trips
with unknown-field pass-through (journal forward-compat), and `update`'s
shallow-merge is structurally faithful; the fully-typed struct model lands
with Sprint C's serialization work where it pays for itself. Two hard-won
determinism notes: serde_json's DEFAULT float parsing is best-effort (±1 ulp)
— `float_roundtrip` is mandatory for parity — and JS-object insertion-order
semantics require `preserve_order`. Gates passed: the journal fixture replays
through `SceneHandle` to the identical frozen snapshot, and a randomized op
fuzz (3 rounds x 60 entries: adds/updates/moves/subtree-removes/page ops)
holds documents deep-equal at every checkpoint, worldMatrix/worldAABB within
1e-9, renderOrder/parentOf identical, and undo-all bit-equal to the initial
document. No runtime flag yet by design: the app still runs the TS SceneGraph;
the flip is Roadmap 4.3/4.6 (worker embedding + msgpack boundary), for which
this port is the substrate. Ported so far: geometry, shapes, spatial,
booleans, scene+commands.

**Sprint C complete (2026-08-01) — the engine-port track (P1–P3) is done.**
`constraints.rs`, `serialization.rs`, `hit_test.rs`, `components.rs`, and
`layout.rs` land with their gates green:

- **Serialization**: rmp-serde produces **byte-identical** PFRM output to
  @msgpack/msgpack (verified byte-for-byte on random documents), decoders
  cross-interop, and the v1→v3 migration is semantically identical (the v1
  fallback page id is deterministic in Rust where TS randomizes — masked in
  the gate). `encodeScene` now takes an injectable `savedAt` (host-side
  timestamps, like host-side ids).
- **Hit-testing**: `hitTestAll` (incl. z-order), `nodesInRect` (marquee
  containment rules), and `findDropFrame` agree exactly across random
  scenes; the BOOLEAN branch runs the exact-CSG walk fully inside Rust.
- **Constraints**: bit-exact across the 5×5 constraint matrix (500 cases).
- **Components + layout**: `runDerivedPasses` (instance sync → auto-layout →
  normalize → GC, fixpoint-bounded) reaches identical fixpoints with
  identical materialized ids. Two cross-engine determinism changes were
  required in TS and are permanent contract improvements: the instance sync
  hash now serializes with **canonical JSON** (sorted keys — key insertion
  order is an implementation detail; old stored hashes simply resync once),
  and materialized-node ids come from an **injectable factory**
  (`setMaterializeIdFactory`), per the host-side-ids rule. Rust normalizes
  integral computed floats to JSON integers (`json_num`) to match JS's
  single number type in both canonical JSON and msgpack. Text auto-resize
  stays host-side (interleaved by the host) until Sprint E's HarfBuzz stack.

Remaining in v0.4: the renderer track — Sprint D (WebGPU) and Sprint E
(HarfBuzz text + glyph atlas + the 100k-shape exit test) — plus the P4
`color.ts` port and deferred P5 svg import/export. The engine flip itself
(app running on the Rust SceneGraph via worker + msgpack boundary,
Roadmap 4.3/4.6) now has every substrate module in place.

## Ground rules (from ADR-002)

1. **Module-by-module, never big-bang.** Each engine module is replaced behind
   its existing TypeScript function signatures; a thin `engine/backend.ts`
   switch decides TS vs WASM per module (feature flag in dev, defaults flipped
   as parity is proven).
2. **The file format does not change.** `scene.bin` (PFRM/MessagePack, schema
   v3) and `history.sqlite` are the contract; [schema.fbs](schema.fbs) is the
   reference object model for Rust struct definitions (serde now, FlatBuffers
   when flatc lands per ADR-004).
3. **Differential testing is the gate.** The existing vitest suites (49 tests)
   run against BOTH implementations; a fuzz harness feeds random documents to
   TS and WASM and diffs outputs. A module ships only at 100% parity or with
   documented, intentional improvements (e.g., exact CSG beating flattened
   booleans).

## The three API contracts

The renderer/UI call exactly three engine surfaces; Rust must reproduce them
bit-for-bit before internals are free to change:

1. **SceneGraph** — `addNode / removeNode / moveNode / updateNode / childListOf / parentOf / worldMatrix / worldAABB / renderOrder / zRank / rootIds / pages`. Ids remain strings; matrices remain `{a,b,c,d,e,f}`.
2. **PatchOp** — the JSON op grammar (`add/remove/update/move/page-*/styles-set`) with apply+invert symmetry. Existing journals MUST replay identically (fixture test: a recorded v0.1–v0.3 journal replayed on both engines ends in identical documents).
3. **Derived passes** — `runDerivedPasses(scene)` semantics: instance sync → text autoresize → auto-layout → container normalize → GC, iterated to fixpoint (bounded). Same fixpoints, same iteration bounds.

## WASM embedding plan

- `crates/polyform-core` (cdylib) built with wasm-pack; loaded in the renderer
  (main thread first; Dedicated Worker + SharedArrayBuffer once the renderer
  reads vertex buffers directly, per Technical-Specification §1.1).
- Boundary encoding: msgpack bytes for bulk (documents, subtrees), plain JSON
  for ops (journal parity). No per-node getter chatter across the boundary —
  batch APIs only.
- Determinism: TS numbers are f64 — Rust uses f64 throughout (NOT f32, despite
  the original spec sketch) so differential tests can demand exact equality.
- `newId()` stays host-side (injected), keeping WASM pure and replay-friendly.

## WebGPU renderer (parallel track)

- New `render/webgpu/` backend implementing the same draw-the-scene entry
  points as `canvas2d.ts` (ADR-003); runtime fallback to Canvas2D stays.
- Pipeline: tessellation in Rust (lyon) → vertex/index buffers → instanced
  draws; glyph atlas fed by the P4 text stack; backdrop blur as a scoped
  texture sample (closes F-16); dashed/aligned strokes done properly (F-04).
- Exit test: 100k-shape document pans at 60fps on integrated graphics
  (Product-Overview's headline claim, currently untested at that scale — the
  fuzz harness gains a document generator for this).

## Verification checklist (each module, before flag-flip)

- [ ] vitest suite green against WASM via the backend switch
- [ ] fuzz diff (1k random documents/ops) TS↔WASM: zero divergence
- [ ] recorded-journal replay fixture: identical final scene bytes
- [ ] perf: ≥2x TS on the module's micro-bench, or a written justification
- [ ] bundle size delta noted (wasm binary is asar-unpacked like sql.js, F-06)

## Suggested sequencing

```
Sprint A: crate scaffold + backend switch + geometry/shapes/spatial (P1)   ✅ shipped
Sprint B: booleans exact CSG (P1) + scene/commands (P2) + journal replay fixture   ✅ shipped
Sprint C: layout/constraints/components (P2-P3) + serialization + hit-test   ✅ shipped
Sprint D: WebGPU pipeline to parity on fills/strokes/effects
Sprint E: text stack (HarfBuzz) + glyph atlas + 100k-shape exit test
```

Toolchain: Rust 1.97 + `wasm32-unknown-unknown` + wasm-pack 0.15 on the dev
machine; CI installs the same via `dtolnay/rust-toolchain` + `Swatinem/rust-cache`
and runs `cargo test` + a fresh `build:wasm` before the JS suite (build.yml).
Installer builds use the committed pkg — contributors without Rust can still
dev/build/test the app (parity suite loads the committed binary).
